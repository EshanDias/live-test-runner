## 1. Coverage bars

**Problem.** The bars were a `▌` character drawn into the text
(`before:` decoration), so they took editing space and moved with typing.
Redraws used the line numbers of the measured file, so after an edit the
bars (and the hover) landed on the wrong lines. They could not be hidden.

**Plan.**
- [x] Draw each bar as a thin left border of a whole-line decoration: no text
      shift, breakpoints keep the gutter (the reason the gutter was left in T1).
      Drop the grey "neutral" bars (they only kept the text shift uniform).
- [x] Remember the file's lines as they were measured; while the editor
      differs, match current lines to measured lines (common prefix/suffix +
      LCS on the changed middle). Unchanged lines keep their bar, edited or
      new lines get none until the next measurement. Hover uses the same map.
- [x] Toggle: `liveTestRunner.showCoverageInEditor` (default on) + Show / Hide
      button in the editor title when the file has coverage; hidden also
      hides the coverage hover.
- [x] Unit tests for the line matcher; e2e: edit without saving → bars and
      hover follow the moved lines; toggle hides them.
- [x] Docs: README, guide, changelogs, ai-context.

Done 2026-11-05 on `feat/coverage-gutter` (from `main` @ v3.2.0). Screenshots:
`node e2e/run.js diag-coverage-bars` with `LTR_E2E_CDP_PORT` / `LTR_E2E_SHOTS_DIR`.

**Decided (owner, 2026-11-05): option C** — 1px faded left edge (done). Was open: The left edge still touches
code at column 0. Options compared with real screenshots
(`node e2e/run.js diag-coverage-options`, breakpoints on lines 2 and 11):
- A — hand coverage to VS Code's own display (Testing API `FileCoverage`):
  colours the line-number column, breakpoints unaffected, VS Code's own
  Show Inline Coverage toggle. Needs a TestController; the owner is open to
  trying it (it is the start of "mirror into VS Code's Testing view").
- B — faint background tint on uncovered / partly covered lines (optional
  faint green for covered).
- C — current left edge, 1px and faded.

**Editing rules (owner, 2026-11-05, done):** a wrong bar is worse than no bar.
Ignore spacing inside / at the end of a line but not indentation (code moved
into an untested `if` must lose its bars); moved code loses its bars (owner
rejected keeping them); an edited line loses its bar; less than half the file
left → no bars until save.

**Gap found:** files changed on disk outside the editor (git pull, branch
switch) don't rerun or go stale — bars hide changed lines, but coverage and
totals stay old until a save. Done 2026-11-05 on `feat/external-file-changes` (owner: add it to this release).

**Settings gear (done):** `liveTestRunner.openSettings` — gear in the Test
Explorer title bar, opens Settings filtered to the extension.

**Storage + commands (owner, 2026-11-05, done on `feat/storage-cleanup`):**
clear commands now delete all of a project's cache; Clear All Cached Data;
30-day pruning. Every command tested end to end (e2e `commands`); fixed the
palette versions of Rerun / Debug / Focus / Show Covering Tests and Select
Project Root writing settings without asking.

## 2. More frameworks — "results only" tier

A lighter support level: run a file / one test, pass/fail in tree + gutter,
output, errors, ▷ Debug. No trace, coverage or covering-tests hover. Saves
rerun the saved test file only; browser e2e frameworks don't rerun on save
unless the user turns it on.

- Mocha (`--reporter` file of ours, `--grep`, `.mocharc.*`)
- node:test (`--test-reporter` file of ours, `--test-name-pattern`; detect `node --test` / `from 'node:test'`)
- Playwright (`--reporter=json`, `file:line`, `--grep`; headless)
- Cypress (`cypress run --spec`, `--reporter json`; slow start)

Full support (trace, coverage) for Mocha / node:test later: they run in plain
Node and can load the existing Babel transform through `--require` / `--import`.

## 3. Angular

Angular 21+ runs Vitest through its builder (`ng test`), often with no
`vitest.config.*`. Spike on a fresh `ng new` app first; then either call the
builder or generate a temporary Vitest config from `angular.json` (like CRA).

## 4. Failure on the line + diff

- Red message after the line that threw (from the stack we already parse).
- Hover: **Show diff** (VS Code diff editor, expected ⇄ actual through a
  virtual document provider) and **Dismiss** (until the next run). Cleared
  when the test passes.
- Matchers without expected/actual (e.g. `toThrow`) show the message only.

## 5. AI-agent bridge

Free for users: tools over data the extension already has.
- VS Code language-model tools (`vscode.lm.registerTool`) for Copilot agent mode.
- An MCP server for Claude Code, Cursor and others (also registrable through
  VS Code's MCP server definition API).
- Tools: failing tests, a test's output, covering tests of a line, line
  coverage of a file, run these tests.
